# Текущее состояние и путь к v1

- Актуально на: 2026-07-29
- Текущая версия web/backend: `v1.0.0-beta.6`
- Следующий стабильный тег: `v1.0.0` после закрытия релизных доказательств

Это основная таблица фактического состояния. Старые планы и release notes
остаются историей и не переопределяют её.

## Значения статусов

| Статус | Смысл |
|---|---|
| Готово в beta | Сценарий реализован и покрыт базовыми автоматическими проверками |
| Частично | Полезный путь работает, но остаётся явно описанная граница |
| Эксперимент | Код существует, но не является обычным пользовательским обещанием |
| Концепция | Зафиксировано направление, пользовательской реализации нет |

## Что изменилось в beta.6

- мобильная очередь сначала отправляет изменение coordinator и использует
  relay как fallback, поэтому доступный backend снова становится общей точкой
  видимости для web;
- roaming-ingest принимает legacy-статусы Android, создаёт и удаляет структуру
  чек-листов и пишет activity;
- web периодически обновляет активные списки карточек, чек-листы, метки,
  комментарии и историю без ручной перезагрузки;
- Android закрывает базовый CRUD workspace/board/column/card/checklist и
  поддерживает перенос карточки в любую колонку;
- активная документация и релизные проверки выровнены на текущую версию;
- добавлена концепция универсальной интеграции GitHub/devctl.

## Честные границы

- Rust/PostgreSQL backend остаётся каноническим центром auth, прав и обычного
  принятия общих изменений.
- Web не строит все проекции из входящего sync-log: для активных поверхностей
  используется безопасный polling.
- Android выполняет структурный CRUD, метки, комментарии и безвозвратное
  удаление через доступный coordinator. Offline/relay-first гарантии относятся
  к карточкам и чек-листам.
- Первый телефон или новая доска требуют первичного получения capability от
  доступного узла.
- Локальные snapshot браузера и Android не зашифрованы отдельным ключом
  устройства.
- Import не выполняет merge или destructive restore существующей доски.
- GitHub/devctl пока описаны документом, а не пользовательской функцией.

## Обычный путь

1. Запустить `python bootstrap.py`.
2. Войти или зарегистрироваться.
3. Создать workspace, доску и колонки.
4. Работать с карточками, чек-листами, метками и комментариями.
5. При необходимости подключить Android к узлу и дождаться подготовки досок.
6. Сохранить прикладной backup доски.
7. Остановить stack через `python bootstrap.py stop`; данные остаются в volume.
8. Перед обновлением выполнить `python bootstrap.py update`: updater создаст
   PostgreSQL dump и сохранит rollback images.

## Почему это ещё beta

Основной дефицит теперь не в web CRUD. До stable не хватает воспроизводимых
доказательств для точного релизного commit:

1. двух последовательных `full-local-release`;
2. smoke распакованного release ZIP на Windows и Linux;
3. stop/start, update/rollback и контролируемого restore с проверкой данных;
4. cross-client матрицы web ↔ Android после исправления beta.6;
5. решения о границе Android в обещании stable v1;
6. выбранной лицензии или явного решения распространять код без публичной
   лицензии;
7. финальной проверки артефакта на секреты и generated-каталоги.

Подробная оценка:
[`stable-v1-readiness-2026-07-29.md`](stable-v1-readiness-2026-07-29.md).

## После stable

GitHub/devctl, coordinator-free права, Iroh в браузере, MFA/passkeys,
полнотекстовый conflict UI и destructive import не должны удерживать уже
работающий self-host продукт в beta. Они развиваются отдельными ограниченными
срезами.
