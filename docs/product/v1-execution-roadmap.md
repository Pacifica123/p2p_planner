# Текущее состояние и путь к v1

- Актуально на: 2026-08-21
- Текущая версия web/backend: `v1.0.0-beta.12`
- Следующий стабильный тег: `v1.0.0` после закрытия релизных доказательств

Это основная таблица фактического состояния. Старые планы и release notes
остаются историей и не переопределяют её.

## Значения статусов

| Статус | Смысл |
|---|---|
| Готово в beta | Сценарий реализован и покрыт базовыми автоматическими проверками |
| Частично | Полезный путь работает, но остаётся явно описанная граница |
| Эксперимент | Код существует, но не является обычным пользовательским обещанием |
| Концепция | Зафиксировано направление, пользовательской реализации нет |

## Что изменилось в beta.12

- устранены оба compile blocker beta.11 в production web/backend build;
- браузер получил read-only GitHub fallback и видит новый commit после reboot,
  даже если host control plane ещё не запущен;
- running revision больше не подменяется текущим Git HEAD после devctl push;
- bootstrap встраивает source revision в web image и фиксирует её в stack state;
- Android mobile.9 повторно прошёл typecheck, CRUD contract, Jest и Android
  export без дополнительных изменений.

## Что изменилось в beta.11

- фиксированный status/completed lifecycle карточки удалён из API и клиентов;
  пользовательская колонка стала единственным состоянием;
- checklist snapshot merge стал поэлементным и tombstone-aware, а backend
  получает relay-события параллельно без суммы последовательных timeout;
- оформление доски передаётся отдельным roaming-событием и сохраняется Android
  local-first даже при недоступном LAN-узле;
- web refresh-сессия coalesces параллельные 401 и завершает потерянную сессию
  без request storm;
- web/Android card details наследуют board palette, а Android получил плоские
  звёзды приоритета и облегчённую иерархию чек-листов.

## Что изменилось в beta.10

- web предлагает новый commit `main`, показывает commit message и выполняет
  host-controlled update с progress/maintenance на прежнем URL;
- внешний порт закреплён за stable gateway, а потерянный state восстанавливается
  по Compose labels без молчаливого создания нового узла;
- web и Android получили одно локальное напоминание на карточку без backend или
  relay-синхронизации;
- Android mobile.8 применяет web-настройки темы, плотности, board palette,
  accent, wallpaper и карточек;
- Android source self-update отложен до signed APK/OTA pipeline.

## Что изменилось в beta.9

- checklist roaming переведён с разрушительных full-card snapshot на
  независимые delta событий checklist и checklist item;
- legacy snapshot с отсутствующим пунктом больше не трактует отсутствие как
  удаление;
- activity создаётся только для реально изменившихся полей, а миграция удаляет
  однозначно ложные legacy `card.moved`;
- Android в мобильной сети сразу использует relay для подготовленной доски,
  если сохранённый адрес узла относится к LAN;
- web, Android и подключённый backend показывают свои версии;
- русские формы количества, названия действий и полей выровнены в обоих
  клиентах.

## Что изменилось в beta.8

- удаление карточки разделено на обратимое локальное скрытие и глобальный tombstone;
- глобальное удаление распространяется как зашифрованный `card.delete`;
- старый `card.put` и bootstrap-снимок не могут воскресить tombstoned карточку;
- миграция публикует удаления, сделанные до beta.8;
- Android `1.5.0-mobile.6` понимает тот же lifecycle-контракт.

## Что изменилось в beta.7

- обычный вход и регистрация явно описывают deployment-local границу email;
- чистый второй web-узел можно связать с основным узлом по LAN и перенести ту
  же identity, owned workspaces, доски, содержимое и настройки;
- per-board roaming capability переносится без передачи backend master key;
- каждый backend получил собственный `nodeReplicaId`, поэтому два узла больше
  не создают одинаковый `(replicaId, replicaSeq)` из-за общего workspace ID;
- концепция External Resource разделяет получение сигнала (`SourceConnector`),
  нормализацию (`provider adapter`) и доменную реакцию.

## Что изменилось в beta.6

- мобильная очередь сначала отправляет изменение coordinator и использует
  relay как fallback, поэтому доступный backend снова становится общей точкой
  видимости для web;
- roaming-ingest принимает legacy-статусы Android, создаёт и удаляет структуру
  чек-листов и пишет activity;
- web периодически обновляет активные списки карточек, чек-листы, метки,
  комментарии и историю без ручной перезагрузки;
- Android закрывает базовый CRUD workspace/board/column/card/checklist и
  поддерживает перенос карточки в любую колонку;
- активная документация и релизные проверки выровнены на текущую версию;
- добавлена концепция универсальной интеграции GitHub/devctl.

## Честные границы

- Rust/PostgreSQL backend остаётся каноническим центром auth, прав и обычного
  принятия общих изменений.
- Web не строит все проекции из входящего sync-log: для активных поверхностей
  используется безопасный polling.
- Android выполняет структурный CRUD, метки, комментарии и безвозвратное
  удаление через доступный coordinator. Offline/relay-first гарантии относятся
  к карточкам и чек-листам.
- Первый телефон или новая доска требуют первичного получения capability от
  доступного узла.
- Web-node link v1 работает только на чистом целевом узле и переносит только
  owned workspaces. После link relay-покрытие относится к карточкам и
  чек-листам, а не ко всему структурному CRUD.
- Локальные snapshot браузера и Android не зашифрованы отдельным ключом
  устройства.
- Import не выполняет merge или destructive restore существующей доски.
- GitHub/devctl пока описаны документом, а не пользовательской функцией.

## Обычный путь

1. Запустить `python bootstrap.py`.
2. Войти или зарегистрироваться.
3. Создать workspace, доску и колонки.
4. Работать с карточками, чек-листами, метками и комментариями.
5. При необходимости подключить Android к узлу и дождаться подготовки досок.
6. Сохранить прикладной backup доски.
7. Остановить stack через `python bootstrap.py stop`; данные остаются в volume.
8. Принять web-плашку нового commit либо выполнить `python bootstrap.py update`:
   общий updater создаст PostgreSQL dump и сохранит rollback images.

## Почему это ещё beta

Основной дефицит теперь не в web CRUD. До stable не хватает воспроизводимых
доказательств для точного релизного commit:

1. двух последовательных `full-local-release`;
2. smoke распакованного release ZIP на Windows и Linux;
3. stop/start, update/rollback и контролируемого restore с проверкой данных;
4. cross-client матрицы web ↔ Android и web ↔ web после исправлений beta.12;
5. решения о границе Android в обещании stable v1;
6. выбранной лицензии или явного решения распространять код без публичной
   лицензии;
7. финальной проверки артефакта на секреты и generated-каталоги.

Подробная оценка:
[`stable-v1-readiness-2026-07-29.md`](stable-v1-readiness-2026-07-29.md).

## После stable

GitHub/devctl, coordinator-free права, Iroh в браузере, MFA/passkeys,
полнотекстовый conflict UI и destructive import не должны удерживать уже
работающий self-host продукт в beta. Они развиваются отдельными ограниченными
срезами.
