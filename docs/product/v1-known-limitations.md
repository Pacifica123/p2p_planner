# Известные ограничения v1.0.0-beta.6

Это границы текущей сборки, а не скрытые обещания stable.

## Релиз и развёртывание

- Свежий `full-local-release` для точного beta.6 commit ещё должен быть выполнен
  на машине с Docker, Rust и браузерным runtime.
- Release ZIP необходимо проверить после распаковки на Windows и Linux.
- Первый запуск требует интернет для Docker images и может занять несколько
  минут.
- LAN-режим использует HTTP и предназначен только для доверенной локальной
  сети.
- Docker volume не заменяет внешний backup. Updater создаёт dump, но
  восстановление остаётся отдельной контролируемой операцией.

## Web, local-first и cross-client

- Каноническая проверка прав и общих изменений выполняется backend.
- Web snapshot хранится в браузере без отдельного шифрования.
- Не все входящие sync-события строят проекции напрямую; открытые web-экраны
  опрашивают backend с интервалом 3–30 секунд.
- Поэтому изменение с другого клиента может появиться не мгновенно, а в
  пределах следующего интервала.
- Полноценного интерфейса смыслового merge-конфликта пока нет.

## Android и roaming

- Карточки и чек-листы можно менять local-first и отправлять через
  зашифрованный relay-журнал.
- Создание и изменение workspace, досок, колонок, меток, комментариев, а также
  безвозвратное удаление синхронизированной карточки требуют доступного
  coordinator.
- Новое устройство должно один раз войти через узел и получить capability
  досок.
- Локальный Android snapshot не зашифрован отдельным ключом устройства.
- Отзыв устройства не удаляет уже сохранённые им данные и не выполняет
  автоматическую ротацию ключей всех досок.
- Nostr-релеи передают зашифрованные данные, но видят технический факт
  публикации и анонимный board tag.

## Backup и import

- Прикладной JSON export не является PostgreSQL dump.
- Вложения не входят в bundle.
- Импорт создаёт новую доску и не поддерживает workspace restore, merge или
  destructive replace.
- Исходные ID, авторы, timestamps и старая activity history не переносятся.
- Импорт выполняется последовательностью API-команд, а не одной транзакцией.

## Интеграции

- Provider registry и stub endpoints не означают готовую GitHub-интеграцию.
- `.p2pkanban`, project bindings и devctl receipts пока являются проектной
  концепцией.
- OAuth/PAT storage, webhook verification, retries и field ownership ещё не
  реализованы.

## Безопасность и распространение

- MFA, passkeys и полное E2EE не входят в beta.6.
- Пользователь с ранее разрешённым доступом может сохранить скачанные данные.
- В репозитории пока нет выбранной публичной лицензии. До решения владельца
  нельзя считать код автоматически разрешённым к копированию и изменению.
